Composer redesign · three concepts, each drawn through idle, draft, running, paused · 2026-09-22

The brief is not "move the controls". It is: the composer has no primary action, it spends two permanent rows on setup that rarely changes, every control is the same 12 px grey so nothing has hierarchy, and turn state is a colour on a floating icon. Each concept below fixes those four things a different way. 1 is an IDE/terminal prompt line docked to the pane. 2 is a card whose header is the chat's identity. 3 is a single line with one panel behind one trigger. The send button is back in all three: Enter still sends, but the state of the turn now lives in one button that turns into stop and resume.

Why it fails
  • No send button; while running, an amber pause icon sits where the action should be. The state of the turn is a colour.
  • The project rail and the footer are permanent rows for choices made once per chat. The compact toggle exists to hide the cost.
  • Model, effort, folder, attach, context all render at one weight and one grey. Nothing is first.
  • The working timer is on the rail, away from the control that stops the work.

Recommendation: concept 1. It matches the direction already chosen for the pane chrome (IDE underline tabs), it has the smallest resting height without a compact mode, the status line scales down by dropping words instead of hiding controls, and the state of the turn is in exactly one place: the prompt glyph and the button beside the text. Concept 2 is the strongest if the card material must stay. Concept 3 is the cleanest line but buries the folder, which matters more here than in a consumer chat app. Behaviour changes in all three: a send button exists (Enter still sends); pause and resume are the same button; the compact toggle is deleted; effort is a first-class control; the timer sits with the stop control.
