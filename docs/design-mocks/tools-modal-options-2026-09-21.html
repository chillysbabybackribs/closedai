A · Ledger — the same information, one column, no card chrome

  • One row per tool on a fixed grid: switch, name, what it does, cost, one status dot. Alignment does the work the 31 borders were doing, so the dialog needs 820×560 instead of 1120×880.
  • Sticky group header carries the effect word, the count, the group cost, and the master switch — the same four facts, now in reading order instead of split across the section head and each card footer.
  • Failures become a 5 px dot plus one line at the top; the red text that dominated the grid is no longer the loudest thing on screen.
  • Details open inline under the row, indented to the name column, and only one opens at a time.

B · Rail + pane — five choices first, tools second

  • The five effect groups are the primary navigation, each with its on/total and a bar for the share of the turn it costs. You choose a trust level, then look at tools.
  • The pane shows one group at a time: never more than thirteen rows, so the body stops being a scroll wall as the registry grows.
  • The group summary sentence gets room to read next to its master switch, which is where the consequential decision actually is.
  • Costs the most screen width of the three, and hides four groups behind a click — worth it if tool count keeps growing, not if it stays near thirty.

C · Budget first — open on five lines, not thirty-one cards

  • The number the switches change is the largest thing in the dialog, with a stacked meter showing which group spends it. "Act in the browser" being nine tools for 87 tokens becomes visible at a glance, which no per-card layout ever showed.
  • Groups start collapsed, so the resting state is five rows you can read in a second. Expand only the group you came for.
  • A filter field reaches any tool by name without scrolling, and matches auto-expand their group.
  • Least discoverable of the three: a tool you cannot name and whose group you cannot guess takes two interactions to find.
