Provider subscription rail — options built from registry components

Each strip is the real dock (44 px, popover glass at 85 %, hairline top edge) with the back/forward buttons and tray in place. Chips are composed only from components in components.json: shadcn Button, Badge, Progress, Separator, HoverCard; @kibo-ui Status; @magicui AnimatedCircularProgressBar and NumberTicker. Every row shows the same data so the options compare directly: Codex 72 % (normal), Claude 18 % (low), Antigravity 6 % (critical), Cursor plan only.

Current build (for comparison) custom usage-meter-ring

8 px digits inside a 16 px ring. The arc is the same ink as the digits, 72 and 18 read as the same near-full circle, and Cursor is a dash whose meaning lives only in the tooltip.

A · Mark + number Button variant="ghost" size="xs"

The Sept 29 decision, on the stock button. One component, 11 px tabular figures, level ink on the number only so the brand marks stay themselves. Cursor shows its plan name instead of a placeholder. ~52 px per chip; the row is 210 px wide.

B · Mark + number + bar Button ghost xs Progress className="h-[3px] w-6"

A readable number plus a linear hint. The Radix Progress root is the same primitive the composer's usage card uses, at 3 × 24 px. A bar length is far easier to compare across four chips than arc sweep is, and 72 vs 18 is visible at a glance. Adds ~30 px per chip.

C · Mark + number + status dot Button ghost xs @kibo-ui Status › StatusIndicator

Quiet until it matters. Normal chips are option A. At ≤20 % the kibo Status indicator appears; at ≤10 % it pulses (the `animate-ping` halo, off under reduced motion). Nothing on the rail moves while everything is healthy.

D · Gauge beside the number @magicui AnimatedCircularProgressBar className="size-4" NumberTicker

If a ring is wanted, this is the registry one, used as a 16 px gauge next to a full-size number rather than as a container for a tiny one. The number stays 11 px and animates with the repo's existing NumberTicker when a reading changes. Busiest of the four: mark, gauge and number compete at this size.

E · Plan over number Button variant="ghost" size="sm"

Answers "which plan am I on" without opening anything. Two lines fit the 32 px button, but the 9.5 px plan label is at the edge of legibility on the glass and Cursor still needs a placeholder for its missing number.

When the rail has no room, one button carries the worst reading in a stock Badge instead of the current bare warning icon. The detail is the shadcn HoverCard in the app's .dock-panel skin, one Progress row per window, and it opens for whichever option above is chosen.

Recommendation

B as the default (number + Progress bar), with C's status indicator reserved for critical if you want a pulse, and F as the collapsed state and detail card. Everything is a stock component with tokens only: no ring module, no bespoke pill surface, and the rail returns to the "mark plus text on the existing rail" rule from the 29th. If you prefer the quietest rail, A alone is the same thing without the bar.
